## 2. Detailed Shot Specifications

### Shot `nwb-shot-01`: Voucher Invoicing Builder (UI Screenshot)
* **Target Section:** `next-web-business-s2-context` & `next-web-business-s4-decisions`
* **Subject:** The primary commercial voucher / invoice creation screen showing line items, item search dropdown, quantity/rate inputs, dynamic discount toggles, and computed CGST/SGST taxes.
* **Viewport & Environment:**
  - Viewport: Desktop 1440×900px or 1920×1200px.
  - Browser Chrome: Minimalist flat dark-slate header or borderless window container with subtle 1px border (`#334155`).
* **Required Test Data:**
  - Seller: Realistic dummy entity (e.g., *"Apex Industrial Supplies Pvt Ltd"*).
  - Buyer: Realistic dummy client (e.g., *"Zenith Fabrication Works"*).
  - GSTIN: Valid synthetic format (e.g., `23AAAAA0000A1Z5` for MP / `27AAAAA0000A1Z5` for Maharashtra).
  - Line Items: 3–4 realistic technical items (e.g., *"CNC Machined Steel Flanges"*, *"Hydraulic Seals"*, *"Industrial Fasteners"*).
* **Strict Redaction Boundaries:**
  - **MANDATORY:** Zero real customer names, live phone numbers, bank account numbers, IFSC codes, or proprietary product prices from the production account.
  - All party addresses must be sanitized placeholders (e.g., *"Sector 3, Pithampur Industrial Area, Indore, MP"*).

### Shot `nwb-shot-02`: Compiled QuestPDF Invoice Document (Document Render)
* **Target Section:** `next-web-business-s4-decisions` (Document Rendering Microservice)
* **Subject:** The final rendered PDF document generated by the ASP.NET Core QuestPDF service.
* **Layout Structure:**
  - A4 aspect ratio with clean typography, header logo, structured buyer/consignee address boxes, zebra-striped line-item table, and bottom HSN/SAC summary table.
  - Number-to-words currency footer (e.g., *"Forty-Seven Thousand Two Hundred Rupees Only"*).
  - Authorized signatory stamp and QR code placeholder.
* **Framing:**
  - Centered document sheet with subtle drop shadow (`box-shadow: 0 20px 40px rgba(0,0,0,0.12)`) on an off-white or charcoal background canvas.

### Shot `nwb-shot-03`: FIFO Inventory Lot Ledger (UI Screenshot)
* **Target Section:** `next-web-business-s5-challenge` (ACID Concurrency & Inventory Batches)
* **Subject:** The inventory lot tracking ledger showing batched stock entries, FIFO lot sequence numbers, current branch quantity, and transactional balance logs.
* **Visual Focus:** Highlight the batch consumption breakdown showing how a single large sales invoice depletes multiple smaller historical inventory lots.
* **Redaction:** Sanitize internal warehouse names and supplier cost figures.

### Shot `nwb-shot-04`: GST Accounting Register & Manual Reconciliation
* **Target Section:** `next-web-business-s2-context` (Financial Compliance)
* **Subject:** The sales and purchase register view filtered by date range and status (`Approved`, `Paid`, `Pending`).
* **Visual Focus:** Demonstrates search filters, place-of-supply tags, tax category totals, and reconciliation status indicators.
* **Redaction:** Blur all real customer identities and specific tax ledger IDs.

## 3. Architecture Diagrams & Code Visuals

### Diagram `nwb-diag-01`: QuestPDF Reverse JSON Hydration Pipeline
* **Format:** Interactive Mermaid sequence diagram embedded in markdown + vector SVG asset.
* **Key Components Illustrated:**
  1. Browser React client requests `GET /render/{model}/{id}` passing Bearer JWT.
  2. .NET Microservice captures request context and proxies upstream to Express `GET /api/{model}/{id}/print`.
  3. Express queries MongoDB replica set and returns populated JSON payload.
  4. QuestPDF compiles binary vector stream and flushes directly to client `<iframe>`.

### Diagram `nwb-diag-02`: Three-Tier Tenancy Scoping
* **Format:** Block diagram illustrating how database operations are partitioned across `user` (account root), `business` (workspace), and `location` (warehouse/store).

## 4. Quality & Delivery Standards

* **Resolution:** All UI captures must be high-DPI (2x pixel density, minimum 1920px wide).
* **Compression:** Optimized to WebP format targeting $< 250\text{ KB}$ per image.
* **Accessibility:** Every visual must include descriptive `alt` text detailing the demonstrated technical pattern (e.g., *"Next Web Business invoicing interface showing multi-line GST calculations and tax breakdown"*).
